## HMR 并发编辑修正

审查发现初版验证脚本在正常流程中无条件还原 TSX/CSS，会覆盖验证期间的编辑器保存。修正前先在隔离副本重放真实 Chrome 的 HMR 截图阶段反例：两份编辑都丢失，脚本仍以 0 退出并报告 16 组通过。

修正后，实际浏览器脚本使用 `withHmrEdits` 统一核对临时写入、正常还原和异常清理；逐份处理文件并汇总错误，浏览器清理也覆盖导航失败与证据保存失败。以下真实浏览器反例均执行实际验证入口，使用独立源码副本和 localhost 服务；每次都记录浏览器 `close()` 调用一次，并确认临时服务退出。源码哈希、逐文件内容比较和诊断见 [hmr-restore-regression.json](evidence/preview/hmr-restore-regression.json)。

| 场景 | 实际结果 |
| --- | --- |
| 无并发修改 | 退出 0，完整 16 组通过；TSX/CSS 草稿保留、HTML 重载，三份源码逐字还原 |
| HMR 截图阶段同时保存 TSX 与 CSS | 退出 1，记录 failed；两份编辑逐字保留，报告两个冲突路径，HTML 保持原始内容 |
| 截图故障与 TSX 编辑同时发生 | 退出 1，同时保留截图故障与冲突诊断；TSX 编辑不变，CSS 和 HTML 正常还原 |
| HTML 最终清理前保存编辑 | 退出 1，保留 HTML 编辑；TSX 和 CSS 已还原 |
| 浏览器首次导航失败 | 退出 1，保留导航错误，浏览器仍关闭 |
| 导航失败后证据保存也失败 | 退出 1，两种错误均出现在诊断中，浏览器关闭不依赖证据写入成功 |

新增 7 项无浏览器回归通过隔离 Bun 子进程验证文件字节、退出码与诊断，还覆盖初次写入前的编辑和还原目标变为目录的读取失败。一份文件冲突或失败时，其他无冲突文件仍完成还原。运行 `bun run test:preview` 可复验这些边界。

本次修正只改变开发验证工具、源码侧测试入口和文档，生产组件、构建与宿主适配未改动，因此复用初版及独立审查的本地包/宿主结论。PR 的新 head CI 会重新生成和检查当前安装包；由于 package.json 的开发脚本变化，新归档哈希应以新 CI 为准。

## 范围与限制

此验收覆盖共享 UI 的合成状态与交互，不评估模型判定准确率，不执行自然语言规则匹配。预览的明暗色值是宿主变量的代表性注入；宿主主题和语言仍由真实 DSH 管理。Hook 顺序/组件身份变化可能重挂载；服务器与 fixture 改动需要重启服务并刷新页面。无冲突的正常验收会还原 HMR 标记与样式；冲突时保留当前文件供开发者检查。

实际使用中的 DSH profile 未被修改或重启。本次交付不包含 UI 库选型、整体 UI 重设计、完整 i18n 审校、共享工具包或第二插件接入。
